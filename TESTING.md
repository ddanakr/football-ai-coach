# TESTING.md — стандарты тестирования и эдж-кейсы

Правила обязательны для всех агентов. Подключено из `CLAUDE.md`.

## 1. Культура тестирования (TDD)

1. **Для каждой новой функции и класса логики пишется юнит-тест на `pytest`, до кода или вместе с ним.** Код без теста не принимается и не коммитится.
2. **Исправление ошибки начинается с теста.** Сначала тест, который воспроизводит ошибку и падает, затем исправление. Регрессионный тест остаётся навсегда.
3. Красный тест в историю не попадает: он коммитится вместе с кодом, который его проходит (см. `GIT.md`).
4. Тесты детерминированы: фиксированные `seed`, никаких `sleep`, никакого реального времени и сети.
5. Имя теста: `test_<что>_<условие>_<результат>`; структура Arrange, Act, Assert; один тест проверяет одну мысль.
6. Таблицы входов и ожиданий оформляются через `@pytest.mark.parametrize`, а не копированием тестов.
7. Для инвариантов (преобразование времени, NMS, метрики) желательно property-based тесты (`hypothesis`). Добавление зависимости согласуется с пользователем.
8. Тесты типизированы так же строго, как код (`mypy --strict`).

## 2. Покрытие

- **Не ниже 80%** (по строкам и ветвям) для модулей обработки данных и ML-пайплайнов: `domain`, `ingest`, `scoreboard`, `spotting`, `speech`, `fusion`, `store`, `agent`, `eval`, `export`.
- Из расчёта исключены `ui/`, `cli.py` и тонкие обёртки, которые только вызывают стороннюю модель. Логика (разбор, нормализация, пороги, решения) выносится в чистые функции, и они покрываются в полном объёме.
- `# pragma: no cover` допустим только на строках, которые вызывают настоящую модель или внешний сервис, и только с комментарием-причиной.
- Падение покрытия ниже порога ломает `python scripts/check.py`. Занижать порог или расширять исключения ради прохождения запрещено.

```toml
# pyproject.toml (фрагмент)
[tool.pytest.ini_options]
minversion = "8.0"
testpaths = ["tests"]
addopts = "-ra --strict-markers --strict-config --disable-socket"
markers = [
  "unit: быстрые изолированные тесты",
  "integration: несколько модулей вместе, без сети (допустим ffmpeg)",
  "data_validation: контракты данных, схемы, конфиги",
  "real_data: требует локальных данных матча, по умолчанию пропускается",
  "slow: долгие тесты",
]

[tool.coverage.run]
source = ["src/aicoach"]
branch = true
omit = ["src/aicoach/ui/*", "src/aicoach/cli.py", "*/__main__.py"]

[tool.coverage.report]
fail_under = 80
show_missing = true
exclude_also = ["if TYPE_CHECKING:", "raise NotImplementedError"]
```

## 3. Эдж-кейсы: запрещено писать только под «идеальные» данные

**Правила:**

1. Для каждой публичной функции есть тесты минимум на: пустой вход, граничные значения, некорректный тип или значение (`None`, `NaN`, отрицательное, слишком большое), путь с ошибкой (исключение нужного типа и понятное сообщение).
2. Функция, которая читает данные из мира (OCR, ASR, ответ модели, файл, API), должна иметь тест на мусорный и неполный вход.
3. Любой новый эдж-кейс, найденный на реальном матче, превращается в тест в тот же день (и в строку этой таблицы, если он доменный).
4. Не делить на ноль, не возвращать `NaN`, не падать на пустом списке: поведение определено и проверено.

**Доменные эдж-кейсы футбола (минимальный обязательный набор):**

### Время и табло

| Кейс | Ожидаемое поведение |
| --- | --- |
| Добавленное время «45+2'», «90+4'» | парсер даёт (тайм, минута, добавленные), сравнение и сортировка корректны |
| Начало 2-го тайма с часами 45:00 | сопоставление `t_v → минута` строится отдельно для каждого тайма |
| Перерыв, предматчевая студия, реклама | событий нет; `t_v` не приравнивается к игровому времени; нет интерполяции через перерыв |
| Табло пропало (повтор, студия) | `clock = None`, запись `warning`; экстраполяция не дольше заданного порога |
| Часы из OCR идут назад или скачут | значение отбрасывается фильтром, запись `warning`, сопоставление не ломается |
| OCR путает цифры (1/7, 0/8, 5/6) | значения вне допустимого диапазона отбрасываются |
| Игра остановлена (травма, дождь), часы стоят | регрессия `t_v → минута` не делит на ноль |
| Видео начинается посреди матча или обрывается | тайм и минута могут быть `None`; пайплайн не падает |
| Серия пенальти после матча | не считается голами матча (`period = shootout`) |

### Голы, замены, карточки

| Кейс | Ожидаемое поведение |
| --- | --- |
| Счёт 0:0 → 1:0 | событие `goal`, команда по стороне, выросшей на табло |
| Счёт вырос и вернулся (VAR) | `status = disallowed`, в метриках как `shot`; не удаляется |
| Два гола подряд за короткий интервал | два события, окна поиска не склеиваются |
| Плашка «ГОЛ» без смены счёта и наоборот | одно событие с источниками; не дубль и не потеря |
| Автогол | счёт у одной команды, автор из другой; флаг `own_goal` |
| Гол с пенальти | `shot` не дублируется |
| Повтор гола в эфире | второй `goal` не создаётся; повтор подавляется в пользу оригинала |
| Несколько замен подряд или одной плашкой | каждая замена отдельное событие |
| Плашка замены с обрезанным OCR текстом | событие сохраняется, `player = None`, уверенность понижена |
| Жёлтая, затем вторая жёлтая и красная | корректная цепочка, не две красные |
| Прямая красная без жёлтой; карточка запасному | не падает, события создаются |
| Карточка без найденного фола; фол без карточки | карточка порождает `foul` с источником `plate`; фол без карточки остаётся от модели |

### Угловые, удары, пики

| Кейс | Ожидаемое поведение |
| --- | --- |
| Два угловых подряд | два события, если расстояние больше окна NMS |
| Удар и угловой в одном окне | оба сохраняются как разные классы |
| События одного класса ближе окна NMS | остаётся с максимальной оценкой; при равенстве порядок детерминирован |
| Оценки модели с `NaN` или пустой массив | `SpottingError` с понятным текстом, без тихого пропуска |

### Видео, аудио, экспорт

| Кейс | Ожидаемое поведение |
| --- | --- |
| Клип у границ: `T−8 < 0`, `T+12 > длина` | границы обрезаются до `[0, длина]`; событие в последнем кадре даёт клип не короче одного кадра |
| Переменная частота кадров, 25 и 30 fps | время из `pts`, а не из `индекс / fps` с жёстким значением |
| Аудио и видео разной длины | смещение учитывается, нет падения |
| Нет GPU или не хватило памяти | понятная ошибка или явный переход на CPU по конфигу |
| Битый или обрезанный файл | `IngestError`, частичные файлы удаляются |

### Имена и речь

| Кейс | Ожидаемое поведение |
| --- | --- |
| Казахские буквы Ә Ө Ү Ұ Қ Ғ Ң Һ І | нормализация; «Ануарбеков» находит «ӘНУАРБЕКОВ» |
| Гомоглифы (латинская A, K, O вместо кириллических) | приводятся к одному виду перед сравнением |
| Двойные фамилии, дефис, регистр, падежные окончания | совпадение по основе |
| Одинаковые фамилии у игроков разных команд | различаются по команде и номеру, не склеиваются |
| Реплика на двух языках, перекрывающаяся речь | язык из `{ru, kk}`; перекрытие допускается как потеря, но без падения |
| Пустой транскрипт, тишина | пустой результат, а не ошибка |
| Галлюцинация Whisper (одна фраза повторена много раз) | отсекается порогами |

### Метрики

| Кейс | Ожидаемое поведение |
| --- | --- |
| 0 предсказаний, 0 эталонных, оба 0 | Precision, Recall, AP определены по правилу (`0.0` или `None`), без `ZeroDivisionError` и `NaN` |
| Одно предсказание подходит двум эталонным | каждый эталон используется один раз |
| Ошибка ровно на границе допуска (±5,0 с) | включительно |
| Допуск SoccerNet (ширина окна, ±δ/2) и наш ±tol | параметр явный, тест на обе трактовки |
| Дубли предсказаний с равной оценкой | детерминированный порядок |

### Агент и хранилище

| Кейс | Ожидаемое поведение |
| --- | --- |
| Вопрос про игрока, которого нет в словаре | «в данных нет», без выдумки |
| Вопрос на казахском или на смеси языков | ответ на языке вопроса |
| Модель вернула несуществующий идентификатор или число, которого не было в результатах инструментов | валидатор отклоняет, ответ перегенерируется или помечается |
| В транскрипте или плашке есть текст-инструкция («забудь правила») | трактуется как данные, поведение не меняется |
| Событие `auto` с низкой уверенностью | в ответе есть оговорка |
| Пустая база событий | ответ без падения |
| Сдвиг события за пределы видео | отказ с ошибкой валидации |
| Правка, затем откат | возвращается предыдущее состояние |
| Добавление события, дублирующего существующее | предупреждение или слияние по правилу |
| Правка уже проверенного (`verified`) события | работает и записывается в журнал |
| Чтение во время записи (WAL) | чтение не блокируется и не получает полузаписанное состояние |
| Повторный запуск стадии | результат тот же, дублей нет (идемпотентность) |

### Вход и внешние сервисы

| Кейс | Ожидаемое поведение |
| --- | --- |
| Некорректная ссылка, приватное или недоступное видео, незавершённая трансляция | `IngestError` с понятным текстом |
| LLM API: таймаут, 429, 5xx | повтор с задержкой, затем `ExternalServiceError`; ответ не придумывается |
| Ответ модели не соответствует схеме | отклоняется, один повтор, затем ошибка |

## 4. Моки и фикстуры

- Тесты работают **локально, быстро и без интернета**. В `pyproject.toml` стоит `--disable-socket` (плагин `pytest-socket`), поэтому любая сетевая попытка падает.
- `conftest.py` содержит автоматическую фикстуру (`autouse`), которая выставляет `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` и подставляет временные `data_dir` и настройки через `tmp_path`.
- **Внешние обращения мокируются на границе, а не внутри библиотек:** через `Protocol`-интерфейсы и тестовые реализации. Например: `FakeDownloader` вместо `yt-dlp`, `FakeLLMClient` с заготовленными структурированными ответами, `FakeWhisper` с готовыми сегментами, `FakeOCR`. Для HTTP-вызовов, которые остались, используется мок-библиотека (`respx` или `responses`; зависимость согласуется).
- **Используй фикстуры `pytest`** для общей подготовки (`settings`, `tmp_db`, `fake_llm`, `event_factory`, `synthetic_video`) и фабрики в `tests/fixtures/factories.py`. Не копируй подготовку между тестами.
- **Данные только синтетические.** Кадры плашек и табло рисуются в тесте (`Pillow`), короткое видео собирается через `ffmpeg` (`lavfi`, 2–3 секунды), транскрипты и разметка маленькие JSON. Реальные кадры, клипы и видео КПЛ и SoccerNet в `tests/` не хранятся.
- Тесты, которым нужен реальный матч, помечены `@pytest.mark.real_data`, пропускаются без локальных данных и не входят в `python scripts/check.py`.
- Настоящие модели (Whisper, ResNet, NetVLAD++) в юнит-тестах не загружаются. Их поведение имитируют заготовленные выходы.

```

├── conftest.py                  # блокировка сети, офлайн-переменные, общие фикстуры

│   ├── scoreboard/              # PNG, сгенерированные Pillow
│   ├── transcripts/             # маленькие JSON
│   └── labels/                  # синтетическая разметка

│   ├── spotting/     test_nms.py            test_peaks.py

│   ├── fusion/       test_rules.py          test_replay_suppression.py
│   ├── eval/         test_matching.py       test_metrics.py            test_bootstrap.py
│   ├── store/        test_edits_log.py      test_events_view.py
│   ├── agent/        test_tools.py          test_citation_validator.py
│   └── export/       test_clip_bounds.py
```

## 6. Чек-лист перед завершением задачи

- [ ] Для каждой новой функции есть тест, написанный до или вместе с кодом.
- [ ] Покрыты пустой, граничный, некорректный вход и путь с ошибкой.
- [ ] Затронутые доменные эдж-кейсы из раздела 3 покрыты (или добавлена новая строка).
- [ ] Нет обращений к сети, реальным моделям и реальным видео в тестах.
- [ ] Покрытие модулей логики не ниже 80%.
- [ ] `python scripts/check.py` зелёный.
