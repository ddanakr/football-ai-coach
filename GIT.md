# GIT.md — стандарты контроля версий

Правила действуют для людей и агентов. Подключено из `CLAUDE.md`.

## 1. Ветки

- `main` всегда рабочая: на ней проходит `python scripts/check.py`. Коммитить в `main` напрямую нельзя, только через ветку.
- Формат имени: `<type>/<task-id>-<kebab-description>`

| Тип | Когда |
| --- | --- |
| `feat/` | новая функциональность |
| `fix/` | исправление ошибки |
| `refactor/` | изменение структуры без смены поведения |
| `test/` | только тесты |
| `docs/` | только документация |
| `chore/` | инфраструктура, зависимости, конфиги |
| `exp/` | эксперимент (сравнение веток A и B, подбор окон); может не вливаться, но результат записывается в `MEMORY.md` |

- `<task-id>`: номер требования из ТЗ (`FR-6`), либо идентификатор этапа плана (`D05` для дня 5), либо `EXP-<n>` для экспериментов. Если ничего не подходит, спроси пользователя; не придумывай номера.
- Описание: латиница в нижнем регистре, дефисы, до 40 символов.
- Примеры: `feat/FR-6-edits-log`, `fix/FR-3-added-time-parsing`, `refactor/D05-score-history`, `exp/EXP-1-branch-a-vs-b`.
- Одна ветка равна одной задаче. Не смешивай несколько задач в одной ветке.

## 2. Коммиты (Conventional Commits)

Формат:

```
<type>(<scope>): <subject>

<body: что и почему, а не как>

Refs: FR-6
```

- **Типы:** `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `chore`, `build`, `ci`.
- **Scope** это имя модуля: `ingest`, `scoreboard`, `spotting`, `speech`, `fusion`, `storage`, `agent`, `eval`, `export`, `ui`, `config`, `deps`, `memory`.
- **Subject:** английский, повелительное наклонение, до 72 символов, без точки в конце.
- **Body** обязателен, если изменение не очевидно из заголовка (причина, компромисс, ссылка на `D-xxx` из `MEMORY.md`).
- **Breaking change:** `!` после scope и пояснение в body (например, меняется схема базы).
- Примеры:
  - `feat(scoreboard): parse added time like 45+2 from the clock`
  - `fix(eval): return zero recall when ground truth is empty`
  - `refactor(fusion): extract replay suppression into its own function`
  - `chore(deps): pin mlflow to a tested version`
  - `docs(memory): record decision D-010 on goal search window`

## 3. Группировка и качество коммита

1. **Логически связанные изменения идут в один коммит.** Функция, её тесты и обновлённая документация этого изменения коммитятся вместе. Не дроби одну мысль на пять коммитов и не склеивай разные мысли в один.
2. **Не смешивай** функциональность и рефакторинг, исправление и форматирование. Если рефакторинг нужен для задачи, он идёт отдельным коммитом перед ней.
3. **Каждый коммит рабочий.** Перед коммитом проходит `python scripts/check.py` (линтер, типы, тесты, покрытие). Нельзя коммитить:
   - неработающий код и падающие тесты;
   - недописанные тесты, пустые тест-функции, `skip` и `xfail` без причины и ссылки на задачу;
   - `TODO` вместо реализации в коде, который заявлен как готовый.
4. **TDD и коммиты.** Красный тест живёт в рабочей директории. В историю он попадает только вместе с кодом, который его проходит.
5. `WIP`-коммиты и `--no-verify` запрещены.
6. Перед коммитом посмотри `git status` и `git diff --staged`: в коммите только то, что относится к задаче.

## 4. Что запрещено хранить в git

Видео, аудио, кадры, клипы, веса моделей, `mlruns/`, `data/`, `.env`, ключи и токены, `*.ipynb`. Эти пути в `.gitignore`, а хуки `pre-commit` блокируют крупные файлы и блокноты.

Если такой файл всё же попал в коммит: остановись, сообщи пользователю. Секрет считается скомпрометированным, его нужно заменить. Переписывать историю без прямой просьбы нельзя.

## 5. Операции, которые требуют явного «да» в чате

Агент вправе создавать ветки и делать коммиты локально. Остальное только после явного разрешения пользователя:

- `git push` (любой), `git merge`, `git rebase`, `git reset --hard`, `git clean`, удаление веток и тегов;
- `--force` и `--force-with-lease`;
- изменение уже опубликованных коммитов (`amend` после push).

Слияние в `main` делается по просьбе пользователя, с `--no-ff`, чтобы ветка читалась как единица работы.

## 6. Pre-commit

В `.pre-commit-config.yaml` минимум: `ruff` (проверка и форматирование), `mypy`, запрет `*.ipynb`, запрет файлов больше 1 МБ, поиск секретов, проверка формата сообщения коммита, запрет подписей ИИ-авторства в сообщении коммита (раздел 7). Установка и запуск описаны в `SKILLS.md`.

## 7. Никаких следов ИИ-авторства

- Запрещены `Co-Authored-By`, «Generated with Claude Code», адрес `noreply@anthropic.com` и ссылки на ИИ-инструменты как на авторов: в сообщениях коммитов, описаниях PR, коде, комментариях, README и документации. Упоминать слово Claude в обычном тексте (например, как название модели или API) можно.
- Автор всех коммитов только владелец репозитория (`user.name` и `user.email` из git-конфигурации).
- Подпись Claude Code отключена в `.claude/settings.json`. Хук `commit-msg` в `.pre-commit-config.yaml` отклоняет сообщение с подписью, ревьюер проверяет `git log --format=%B main..HEAD`.
- Уже опубликованные коммиты с подписью не переписываются без прямой просьбы (раздел 5): агент сообщает о них пользователю.
