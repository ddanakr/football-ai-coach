# Football AI Coach

## 1. Что это

Football AI Coach берёт запись матча КПЛ из трансляции KFF LEAGUE на YouTube и строит каталог событий пяти категорий: гол, удар, угловой, фол, замена. У каждого события есть время в секундах видео, тайм, игровая минута, команда (если известна) и источник. Аналитик просматривает события в интерфейсе (плеер, таблица, ручные правки, клипы и ролики, режим проверки), а агент отвечает на вопросы по матчу на русском и казахском со ссылками на моменты видео.

Идея гибридная. Плашки и табло трансляции почти детерминированно дают замены, голы и карточки. Готовая модель SoccerNet (T-DEED) даёт удары, угловые и фолы. Языковая модель отвечает на вопросы, но время событий не выдумывает: таймкоды и числа она получает из инструментов, а ссылки на моменты подставляет интерфейс.

Демо-видео: https://drive.google.com/file/d/1a8d1Vs4ZXb4kGaUw7cHGd2VXn_iVIUGT/view?usp=sharing

Проект P01 программы KOZ AI, спринт 14 дней, один разработчик.

Сверх задания сделано, одной строкой каждое:

## 3. Результаты

Числа взяты из [docs/metrics.md](docs/metrics.md) (генерируются командами `final-eval`, `review-eval`, `corner-eval`); краткий отчёт о пользе, стоимости и внедрении: [docs/report.md](docs/report.md).

**Оговорки.** Один матч, один размечающий, пилот. Пороги и смещения подбирались на 1-м тайме, итог считается на 2-м; 2-й тайм не был полностью слепым (до итогового расчёта смотрели число фолов агента и беглое сравнение с Gemini). Эталон 2-го тайма размечен вторым проходом. Это не запуски MLflow. Допуск ±T — половина окна сопоставления (см. раздел 7).

**2-й тайм (тест), основная система (c), допуск ±5 с.** Отметок эталона: 45 (гол 1, удар 15, угловой 6, фол 18, замена 5).

| Класс | TP | FP | FN | Precision | Recall |
| --- | ---: | ---: | ---: | ---: | ---: |
| гол | 1 | 0 | 0 | 1.000 | 1.000 |
| удар | 4 | 5 | 11 | 0.444 | 0.267 |
| угловой | 6 | 0 | 0 | 1.000 | 1.000 |
| фол | 14 | 26 | 4 | 0.350 | 0.778 |
| замена | 5 | 0 | 0 | 1.000 | 1.000 |
| все (micro) | 30 | 31 | 15 | 0.492 | 0.667 |

Для всех классов вместе: Precision 0.492 (95 % CI 0.361–0.623), Recall 0.667 (0.511–0.800), F1 0.566; ошибка таймкода: медиана 1.11 с, P90 2.15 с. При допуске ±10 с: Precision 0.508, Recall 0.689, F1 0.585 (P90 ошибки 2.65 с). Правок до идеального списка: 46 при ±5 с (31 удаление и 15 добавлений). Классы с одной-шестью отметками (гол, угловой, замена) дают интервалы, которые ничего не говорят о точности: цифры 1.000 это «не ошиблись на этом матче».

**Сравнение систем, 2-й тайм.**

| Система | P ±5 | R ±5 | F1 ±5 | R ±10 | Медиана ошибки, с | P90 ошибки, с |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| (a) без модели: табло и плашки | 0.778 | 0.156 | 0.259 | 0.178 | 1.41 | 2.37 |
| (b) T-DEED без слияния, порог 0.2 | 0.452 | 0.622 | 0.523 | 0.622 | 1.19 | 2.29 |
| (c) слияние с моделью (основная) | 0.492 | 0.667 | 0.566 | 0.689 | 1.11 | 2.15 |
| (d) Gemini-база (один заранее записанный запрос, не повторяется пакетно) | 0.368 | 0.156 | 0.219 | 0.222 | 0.86 | 3.10 |

Вывод осторожный: без модели система точна, но находит мало; модель поднимает Recall ценой ложных ударов и фолов, слабее всего удары (Recall 0.267) и фолы (Precision 0.350). 1-й тайм (подбор, цифры оптимистичны): Precision 0.696, Recall 0.889 при ±5 с.

**Режим проверки (D-075).** Если аналитик просматривает не только события, но и кандидаты-удары модели, Recall объединения при ±5 с на 2-м тайме 0.844 (38 из 45) против 0.667 у событий; строк к проверке 79 против 61.

**Агент.** На 23 вопросах (`agent-eval`, `openai/gpt-6-luna`): 20 прошли проверку с первой попытки, 2 со второй, 1 отказ («не удалось подтвердить данными»), ссылок на события 70, ошибок сервиса 0, 0.0096 USD за весь прогон. Правильность ответов по существу в этом прогоне не оценена (поле `grade` пусто); проверка валидатора смысл пересказа не проверяет.

**Время и стоимость обработки одного матча** (полный `ingest` по ссылке): сумма стадий 1607.9 с (26.8 мин) без шага T-DEED; расшифровка комментария 0.5134 USD (47 кусков, `elevenlabs/scribe-v2`); время T-DEED в Colab и стоимость Gemini-базы в метриках не записаны.

## 4. Быстрый старт

**Требования:** Python 3.11, FFmpeg (с `ffprobe`) в `PATH`, Tesseract с языками `kaz` и `rus`. Видеокарта для просмотра и правок не нужна; для обработки нового матча нужна видеокарта или калибровка образцов табло в режиме процессора (раздел 5).

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

FFmpeg: сборка в `PATH`. Tesseract: установщик с языками `kaz` и `rus`; проверка `tesseract --list-langs`. Если Tesseract не в `PATH`, задайте `TESSERACT_CMD` в `.env`.

**Linux (Debian/Ubuntu):**

```bash
sudo apt install ffmpeg tesseract-ocr tesseract-ocr-kaz tesseract-ocr-rus fonts-dejavu-core
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

**`.env`.** Откройте `.env` и впишите значение после `=` (без пробелов и кавычек). Файл в `.gitignore`. Приоритет: флаг командной строки, переменная окружения, `.env`, умолчание. Основное:

| Переменная | Зачем |
| --- | --- |
| `OPENROUTER_API_KEY` | ключ OpenRouter; нужен агенту, расшифровке комментария и описаниям по клипам |
| `AICOACH_BUDGET_USD` | потолок платных трат за календарный месяц (UTC); пусто: без потолка; запрос сверх потолка не отправляется |
| `AICOACH_AGENT_MODEL` | модель агента (слаг OpenRouter); пусто: `openai/gpt-6-luna` |
| `AICOACH_VLM_MODEL` | видеомодель описаний и тегов; пусто: `google/gemini-3.7-flash` |
| `AICOACH_DATA_ROOT` | каталог с каталогами матчей (умолчание `--data-root`) |
| `AICOACH_LLM_PROVIDER`, `GEMINI_API_KEY` | необязательно: прямой бесплатный Gemini вместо OpenRouter (`gemini`) |
| `TESSERACT_CMD`, `AICOACH_FONT_FILE` | пути к Tesseract и к шрифту с кириллицей для подписей роликов |

Остальные настройки и их описание: `.env.example`. Без ключа интерфейс, правки, клипы и ролики работают, не работают панель «Агент», описания и теги по клипам.

**Запуск интерфейса с готовым матчем.** Каталог готового матча (видео, `aicoach.db` или `aicoach_model.db`, плашки, табло, расшифровка) в репозиторий не входит, он лежит вне git. Если у вас есть каталог `<DATA>/match01`:

```bash
python -m aicoach.cli ui --video <DATA>/match01/src.mp4 --youtube-id <ID_ВИДЕО> \
    --db <DATA>/match01/aicoach_model.db --data-root <DATA> \
    --templates <DATA>/match01/scoreboard_templates
```

`<ID_ВИДЕО>` — идентификатор видео YouTube (11 знаков; если он начинается с «-», пишите `--youtube-id=<ID>`). `--db` нужен, если база названа не `aicoach.db`. Без `--video` интерфейс открывается без матча, и доступен только блок «Новый матч». Интерфейс: плеер и панель «Агент» сверху, таблица событий с фильтрами под ними, в боковой панели экспорт клипа, ролик по категории, выгрузка разметки, режим проверки, описание эпизода, команды и форма.

Проверка качества кода: `python scripts/check.py` (ruff, ruff format, mypy --strict, pytest с покрытием не ниже 80 %). Установка хуков: `pre-commit install`.

## 5. Обработка нового матча

```bash
python -m aicoach.cli ingest "https://www.youtube.com/watch?v=<ID>" \
    --data-root <DATA> --templates <DIR_С_ОБРАЗЦАМИ_ТАБЛО>
```

Шаги (статусы в `status.json` каталога матча `<DATA>/<id видео>/`): загрузка (`yt-dlp`, не выше 720p, проверка кадра 1280×720), звук 16 кГц, табло, плашки, фамилии с плашек (Tesseract), расшифровка комментария, ожидание файла T-DEED, слияние, слой кандидатов режима проверки, названия команд и цвет формы, теги угловых. Готовое пропускается, второй запуск того же матча отклоняется замком `ingest.lock`. Коды выхода: 0 готово, 3 ждёт файл T-DEED, 2 ошибка. То же делает блок «Новый матч» в интерфейсе (`ui --data-root <DATA> --templates <DIR>`).

**Образцы табло (`--templates`).** Нужны образцы цифр табло, вырезанные из этого же эфира: калибровка идёт вручную в два шага (`scoreboard-calibrate`, описание в `SKILLS.md`). Образцов откалиброванного матча в репозитории нет (`scoreboard_templates/` в `.gitignore`). Образцы и прогон табло должны идти в одном режиме декодирования: образцы демо-матча откалиброваны в режиме видеокарты, поэтому на машине без видеокарты `scoreboard` остановится с ошибкой, пока образцы не откалиброваны в режиме процессора (`--cpu`; для AV1 это в десятки раз медленнее).

### Шаг T-DEED (модель ударов, угловых и фолов)

Модель запускается отдельно, в Colab или на любой машине с видеокартой NVIDIA, **неизменённым** `inference.py` из репозитория T-DEED. Код T-DEED в этот репозиторий не копируется и не импортируется (GPL-3.0, см. раздел 9). Пока файла нет, `ingest` останавливается с кодом 3 и печатает инструкцию.

1. Возьмите `src.mp4` из каталога матча и перекодируйте его в **25 кадров в секунду без обрезки** (шаг модели задан в кадрах и рассчитан на 25 к/с; файл с 60 к/с дал бы 5 к/с выборки и сломал модель). Пример (команда в журнале проекта не записана, не проверена): `ffmpeg -i src.mp4 -r 25 -c:v libx264 -an src_25fps.mp4`.
2. Клонируйте [arturxe2/T-DEED](https://github.com/arturxe2/T-DEED). Код читался на коммите `d953b4d`.
3. Установите зависимости из `requirements.txt` T-DEED (`torch==2.3.1`, `torchvision==0.18.1`, `timm==1.0.3`, `numpy==1.26.4`, CUDA 12.1) и дополнительно `wandb`, `opencv-python`, `SoccerNet`: `inference.py` импортирует их, а в `requirements.txt` их нет.
4. Скачайте чекпойнт `SoccerNet_small` из [папки Google Drive](https://drive.google.com/drive/folders/1sxZalU_hCwL8ITZCU9VqSWE8dB94lJty) (ссылка из README T-DEED) в `checkpoints/SoccerNet/SoccerNet_small/checkpoint_best.pt`. Конфиг `config/SoccerNet/SoccerNet_small.json` лежит в репозитории T-DEED. Использовалась только модель `small`: на 1-м тайме она оказалась лучше `big` и по Recall, и по Precision.
5. Запустите из корня клона (кадры 796×448 — разрешение обучения, порог 0.05 нужен, чтобы выбрать пороги слияния уже у нас):

   ```bash
   python inference.py --model SoccerNet_small --video_path src_25fps.mp4 \
       --frame_width 796 --frame_height 448 --inference_threshold 0.05
   ```

   Результат: `inference_output/results_inference.json`. Размер пачки `batch_size` задан в конфиге (умолчание 8); для готового файла использовалась пачка 2 (так названы файлы `tdeed_SoccerNet_small_thr0.05_bs2.json`). Видеокарта обязательна: `inference.py` жёстко использует `cuda`.
6. Положите результат в каталог матча под именем `tdeed_<имя>.json`, например `tdeed_SoccerNet_small.json` (файл `tdeed_*.json` должен быть один).
7. Повторите ту же команду `ingest`: загрузка, звук, табло и плашки берутся из готового, дальше идёт слияние, слой кандидатов, команды и теги.

## 6. Docker

Образ `aicoach:latest` (только процессор, 1,94 ГБ) запускает интерфейс и команды без ручной установки Python, FFmpeg и Tesseract.

**Работает:** интерфейс, правки, `clip`, `reel`, `export-labels`, `agent-eval`, `final-eval`, `plate-names`, `describe`, `transcribe` по уже обработанному матчу, который подключён томом.

**Не работает: обработка нового матча** (`ingest`, `scoreboard`, `plates`, `run`). В контейнере нет видеокарты, а образцы табло демо-матча откалиброваны в режиме видеокарты, поэтому `scoreboard` в режиме процессора остановится с ошибкой (вывод сделан по коду, остановку агент не запускал). Новый матч обрабатывайте на хосте, а готовый каталог подключайте к Docker. T-DEED в образе нет (запускается отдельно, раздел 5). В образе нет JS-рантайма для `yt-dlp`, скачивание в контейнере не проверялось.

## 7. Воспроизведение метрик

Таблицы [docs/metrics.md](docs/metrics.md) воспроизводятся командами ниже. Им нужен каталог матча вне git (`<MATCH_DIR>`, например `match01`): базы `aicoach_model.db` (с моделью) и `aicoach_nomodel.db` (без модели), файл T-DEED `tdeed_SoccerNet_small_thr0.05_bs2.json`, `gemini_baseline_half2.txt`, расшифровка и заполненный эталон угловых `corner_truth.csv`, а также каталог полного `ingest` (`status.json`) для времени стадий. Эталон разметки `data_labels/match01_ground_truth.json` лежит в репозитории.

```bash
# 1. Итоговые метрики и сравнение систем; пишет docs/metrics.md целиком
python -m aicoach.cli final-eval --match-dir <MATCH_DIR> \
    --tdeed tdeed_SoccerNet_small_thr0.05_bs2.json --ingest-dir <DIR_ПОЛНОГО_INGEST> --final

# 2. Режим проверки: Recall объединения «события + кандидаты» (раздел между маркерами в docs/metrics.md)
python -m aicoach.cli review-eval --match-dir <MATCH_DIR> --tdeed tdeed_SoccerNet_small_thr0.05_bs2.json

# 3. Теги угловых по клипам (раздел между маркерами); 2-й тайм только с --final
python -m aicoach.cli corner-eval --match-dir <MATCH_DIR> --final
```

**2-й тайм тестовый и считается один раз** (`--final`): без `--final` команды выводят только 1-й тайм, на котором подбирались пороги. `final-eval` пишет `docs/metrics.md` целиком и стирает разделы `review-eval` и `corner-eval`, поэтому порядок именно такой. Оценка только 1-го тайма и выбор порогов: `spotting-eval --predictions <tdeed_*.json>`. Цифры не запуски MLflow (запись в MLflow для `eval` не сделана).

### Как считается допуск и формат эталона

Метрики считает `aicoach.eval` (`evaluate(...)`, таблица `format_markdown(report)`). **Допуск `tolerance_s` это половина окна.** Событие найдено, если `|t_pred - t_gt| <= tolerance_s`, граница включена. В SoccerNet параметр δ означает ширину всего окна, поэтому δ = 10 с в SoccerNet соответствует `tolerance_s = 5.0` здесь, а «±5 с» из задания это `tolerance_s = 5.0`. Сопоставление по классам жадное (пары с `|dt| <= tolerance_s` сортируются по `|dt|`; один эталон и одно предсказание участвуют максимум в одной паре). Если делить не на что, Precision и Recall равны `None`, а не 0. Отменённый гол считается ударом. Bootstrap: 1000 ресэмплов, seed 0.

Файл эталона читает `load_ground_truth`: `video`, необязательные `halves` (секунды от начала файла), `events` (`type` из `goal|shot|corner|foul|subst`, `t_v`, `half`; необязательные `clock`, `team`, `visibility`, `replay`, `annotator`, `note`). Протокол разметки: [docs/annotation_protocol.md](docs/annotation_protocol.md).

## 8. Ограничения

- **Подстроено под графику трансляции KFF.** Табло, плашки замен, голов и карточек читаются по цвету, форме и положению, образцы цифр табло режутся из эфира. На другой трансляции, туре или сезоне нужна новая калибровка; раскладка проверена на одном матче.
- **Один матч, пилот.** Классы с единицами отметок (гол, замена, угловой) статистически шаткие; 2-й тайм не был полностью слепым.
- **Удары и фолы слабее остальных.** Для ударов Recall 0.267, для фолов Precision 0.350 на 2-м тайме (раздел 3); команда этих событий часто неизвестна, тогда `team = null`, и агент об этом говорит.
- **Казахский язык агента проверен на 14 вопросах: 11 верно** (оценка автора по `answers_kk.csv`, файл вне репозитория: kk2 неполно, kk16 смешение языков, kk22 отказ), служебные пометки («по клипу, не проверено», «комментатор сказал» и подобные) выводятся на русском. Метки говорящих и язык сегментов расшифровки ненадёжны.
- **Красная карточка не проверена на реальных плашках:** в демо-матче их нет, детектор проверен только на синтетике; вторая жёлтая показывается как жёлтая.
- **Описания эпизодов и теги угловых по клипам не проверены:** это ответ видеомодели, а не факт; поле `zone` (зона подачи) совпало с эталоном в 4 случаях из 8 и помечено «низкая надёжность»; выборка угловых 4 и 6.
- **Агент не помнит прошлые вопросы диалога**, каждый вопрос независим; валидатор не проверяет смысл пересказа, только ссылки, адреса, имена и числа.
- **Время поиска замерено на одном человеке** (пилот; ручное время по памяти размечавшего), эксперимент на двух людях с обоими режимами не проводился.
- **Docker не обрабатывает новый матч** (раздел 6). Видеокарта обязательна для T-DEED; табло и плашки имеют режим процессора (`--cpu`), для AV1 он в десятки раз медленнее.
- **Платные внешние сервисы:** расшифровка, агент и описания идут через OpenRouter; без ключа часть функций недоступна.

## 9. Данные и лицензии

- **T-DEED** (модель ударов, угловых и фолов): репозиторий под GPL-3.0 (так показано на странице проекта). **Код T-DEED в этот репозиторий не включён**: он клонируется отдельно, `inference.py` запускается неизменённым в отдельном процессе, а в репозитории лежит только адаптер его JSON-файла (`src/aicoach/spotting/`).
- **Чекпойнты T-DEED:** в README T-DEED о лицензии и условиях чекпойнтов ничего не сказано, там только ссылка на папку Google Drive. Явного разрешения на их использование нет; веса обучены на данных SoccerNet, условия этих данных не проверены.
- **SoccerNet:** используется только открытая разметка и косвенно веса T-DEED; видео SoccerNet закрыто и не нужно. Условия лицензии данных SoccerNet не проверены.
- **Tesseract** (Apache-2.0), **FFmpeg** (LGPL или GPL, в зависимости от сборки), **yt-dlp** (Unlicense) и остальные зависимости ставятся отдельно и в репозиторий не входят; их условия смотрите на страницах проектов. Зависимости Python перечислены в `pyproject.toml`.
- **Модели через OpenRouter** (агент, расшифровка речи, видеомодель): работают на условиях выбранных поставщиков. Звук комментария и клипы событий отправляются во внешний сервис; не отправляйте материалы, которые для этого не разрешены.
- **Видео, звук, кадры, клипы и веса в репозиторий не попадают** (`.gitignore`, хуки `pre-commit`). Используйте только трансляции, которые вам разрешено скачивать. Список трансляций KFF LEAGUE, разрешённых куратором, и право скачивать их локально остаются неподтверждёнными (открытый вопрос в [MEMORY.md](MEMORY.md)).
- **Эталон** `data_labels/match01_ground_truth.json` — разметка автора проекта (один размечающий); содержит типы и времена событий, не видео.
