# SKILLS.md — процессы и автоматизация

Команды и порядок работы для всех агентов. Подключено из `CLAUDE.md`.

> **Статус команд:** репозиторий создаётся с нуля, поэтому команды ниже описывают целевой вид. Среда разработки Windows (PowerShell) без `make`, `uv`, WSL и Docker (см. D-016 в `MEMORY.md`); общий контроль качества это `python scripts/check.py`. Если команда изменилась или добавилась, обнови этот файл в том же коммите.

## 1. Окружения

Нужны два окружения: основное (PyTorch, Whisper, Streamlit) и отдельное для извлечения признаков ResNet-TF2 (TensorFlow 2). Они конфликтуют по зависимостям, смешивать их нельзя.

```bash
# основное окружение
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pre-commit install
cp .env.example .env        # затем заполнить значения вручную; секреты не коммитить

# окружение признаков (TensorFlow), только для стадии features-tf
python3.11 -m venv .venv-tf && source .venv-tf/bin/activate
pip install -e ".[features-tf]"
```

На Windows (PowerShell) основное окружение создаётся так: `python -m venv .venv`, затем `.venv\Scripts\Activate.ps1` и `pip install -e ".[dev]"`.

**Настройки (D-057, D-060, D-067, D-068).** Девять настроек лежат в одном классе `aicoach.config.Settings` (`pydantic-settings`): `AICOACH_LLM_PROVIDER` (`openrouter`, умолчание, платный путь, или `gemini`, прямой бесплатный; флаг `--provider` важнее), `OPENROUTER_API_KEY` (ключ OpenRouter, нужен при `openrouter`), `AICOACH_AGENT_MODEL` (модель агента для `openrouter`, умолчание `openai/gpt-6-luna`; флаг `--model` важнее; для `gemini` не действует), `AICOACH_BUDGET_USD` (потолок платных трат за календарный месяц UTC в долларах; пусто: без потолка; `0` это настоящий потолок), `GEMINI_API_KEY` (нужен только при `gemini`), `GEMINI_MODEL` (пусто: умолчание из `config.py`), `GEMINI_TRANSCRIBE_MODEL` (модель расшифровки речи, умолчание `gemini-3.5-transcribe`), `AICOACH_DATA_ROOT` (умолчание `--data-root`), `TESSERACT_CMD` (пусто: PATH, затем папки установщика). Приоритет: флаг командной строки, переменная окружения, `.env` в корне репозитория, умолчание (как в Docker и CI); пустое значение считается незаданным. `os.environ` код не меняет: ключ из `.env` не наследуют дочерние процессы. В репозитории только шаблон `.env.example` (все девять строк с комментариями), `.env` и `*.env` в `.gitignore`. Задать: `Copy-Item .env.example .env`, открыть `.env` в редакторе, вписать значение после `=` (без пробелов вокруг `=`, кавычки не нужны). Читает код `aicoach.config.load_settings()` и `read_gemini_api_key()`; нет ключа дают `ConfigError` с подсказкой; неверное значение (`AICOACH_BUDGET_USD=abc`, неизвестный поставщик) это `ConfigError`, в тексте имя настройки без значения.

**Журнал трат и бюджет (D-067).** Каждый платный запрос (агент, расшифровка) пишет строку в `spend_ledger.jsonl`: в `AICOACH_DATA_ROOT`, а если он не задан, в каталоге над каталогом матча (`C:\Projects\data\spend_ledger.jsonl` для `C:\Projects\data\match01`); файл вне git. Поля: время UTC, поставщик, модель, вид (`agent` или `transcribe`), токены, секунды звука, стоимость и основание: `actual` (стоимость из ответа OpenRouter), `estimate` (по таблице цен `agent/pricing.py`, `speech/pricing.py`), `free` (прямой бесплатный Gemini, стоимость 0). Перед платным запросом: потрачено за месяц плюс оценка запроса больше `AICOACH_BUDGET_USD` значит `BudgetExceededError`, запрос не отправляется (`agent-eval` останавливается сразу, панель показывает ошибку). Остаток за месяц: сумма `cost_usd` строк текущего месяца (`python -c` или таблица). Бесплатные запросы бюджет не проверяют. Битая строка журнала это громкая ошибка `StorageError`, а не молчаливо меньшая сумма. Пороги, окна клипов, лимиты и цены в `.env` не кладутся. Агенту чтение и правка `.env` запрещены в `.claude/settings.json`.

**Tesseract (D-059).** Фамилии с плашек читает Tesseract, это отдельная программа, а не пакет Python (пакет `pytesseract` ставится вместе с `pip install -e ".[dev]"`). На Windows: установщик с языками `kaz` и `rus` (проверка: `tesseract --list-langs`); программа ищется по `TESSERACT_CMD` (если задан, но файла нет, возврата к PATH нет: шаг пропускается с причиной), иначе в PATH, затем в `C:\Program Files\Tesseract-OCR` и `C:\Program Files (x86)\Tesseract-OCR`. Без неё (или без одного из двух языков) шаг `plate_names` получает состояние «пропущено» с причиной, остальной пайплайн работает.

**Поиск секретов (D-057).** Хук `detect-secrets` (pre-commit) сверяет изменённые файлы с `.secrets.baseline`. Фиктивный ключ в тесте помечается комментарием `# pragma: allowlist secret` в той же строке. Если хук сработал на ложном срабатывании, которое нельзя пометить pragma, обновить baseline: `pip install detect-secrets==1.5.0` во временном окружении (не в `.venv`), `detect-secrets scan > .secrets.baseline`, `detect-secrets audit .secrets.baseline` (каждое срабатывание разобрать), `git add .secrets.baseline`. Проверка всей истории git отложена до публикации репозитория.

## 3. Запуск пайплайна

Каждая стадия отдельная команда, пропускает готовое и пишет файл в каталог матча (`data/<match_id>/`; для стадии `scoreboard` это каталог видео). Пути и пороги берутся из `.env` и `configs/`, не из аргументов с жёсткими значениями.

```bash
python -m aicoach.cli ingest     "<YOUTUBE_URL>" [--data-root <DATA_DIR>] [--match-id <ID>] [--templates <DIR>/scoreboard_templates] [--cpu]   # ссылка → src.mp4, audio.wav, табло, плашки, фамилии, расшифровка комментария, ожидание T-DEED, слияние в <DATA_DIR>/<ID или id видео>/; код выхода 0 готово, 3 ждёт файл T-DEED, 2 ошибка
python -m aicoach.cli scoreboard --video <PATH_TO_SRC_MP4> [--force]   # часы и счёт табло → scoreboard.json рядом с видео
python -m aicoach.cli scoreboard-calibrate --video <PATH_TO_SRC_MP4> --workdir scratch/<ID>_calibration   # шаг 1: эталон табло и листы кластеров цифр
python -m aicoach.cli scoreboard-calibrate --video <PATH_TO_SRC_MP4> --workdir scratch/<ID>_calibration --labels labels.json   # шаг 2: образцы цифр
python -m aicoach.cli plates     --video <PATH_TO_SRC_MP4> [--match-id <ID>] [--sample-fps 2] [--cpu] [--force]   # плашки замен, голов, карточек → plates.json и plate_crops/ рядом с видео (нужен scoreboard.json)
python -m aicoach.cli plate-names --video <PATH_TO_SRC_MP4> [--match-id <ID>] [--lineups <FILE.csv>] [--force]   # фамилии с плашек (Tesseract kaz+rus) → plate_names.json рядом с видео; нужен plates.json; состав `lineups.csv` рядом с видео (или `--lineups`) необязателен: с ним фамилия сверяется с игроками своей стороны, без него пометка «без сверки»; нет Tesseract: шаг пропущен, код выхода 0
python -m aicoach.cli transcribe --match-dir <MATCH_DIR> [--match-id <ID>] [--lineups <FILE.csv>] [--provider openrouter|gemini] [--model <MODEL>] [--force]   # расшифровка комментария на весь матч (D-070) → transcript.json и speech_chunks/ в каталоге матча; звук из audio.wav, иначе из src.mp4; модель по умолчанию elevenlabs/scribe-v2 через OpenRouter; печатает только числа (сегменты, упоминания игроков, дыры по таймам, стоимость), текст не печатает; нет ключа: шаг пропущен, код выхода 0; `--force` пересобирает transcript.json из сохранённых ответов без новых запросов (чтобы платить заново, удалить speech_chunks/)
python -m aicoach.cli spotting-eval --predictions <PATH_TO_TDEED_JSON> [--ground-truth data_labels/match01_ground_truth.json] [--half 1] [--thresholds 0.05 0.1 0.2 0.3 0.5] [--fps 25] [--radius-s 3] [--output <FILE>]   # оценка T-DEED на 1-м тайме → таблица и eval_<имя>_half1.json рядом с файлом
python -m aicoach.cli features   --match-id <ID>          # в окружении .venv-tf для ветки A
python -m aicoach.cli spot       --match-id <ID> --branch a   # или --branch b
python -m aicoach.cli speech     --match-id <ID>          # VAD, Whisper, лексикон
python -m aicoach.cli fuse       --video <PATH_TO_SRC_MP4> [--predictions <PATH_TO_TDEED_JSON>] [--config <FILE.json>] [--db <FILE>] [--match-id <ID>] [--force] [--discard-edits]   # слияние правилами: события в aicoach.db и candidates.json рядом с видео
python -m aicoach.cli run        --video <PATH_TO_SRC_MP4> [--predictions <PATH_TO_TDEED_JSON>] [--config <FILE.json>] [--match-id <ID>] [--cpu] [--force] [--discard-edits]   # scoreboard, plates, fuse по порядку (модели в нём нет)
python -m aicoach.cli ui         [--video <PATH_TO_SRC_MP4> --youtube-id <ID>] [--data-root <DATA_DIR>] [--templates <DIR>] [--match-id <ID>] [--db <FILE>]   # события в браузере (Streamlit): просмотр и ручные правки (добавить, сдвинуть, сменить тип, удалить, отменить последнюю; пишутся в журнал `edits`, проверка времени по `candidates.json` и `scoreboard.json` рядом с видео); ID видео только параметр; id с «-» в начале писать как --youtube-id=<ID>; путь `--video` передаётся интерфейсу для экспорта клипа (кнопка «Экспорт клипа» в боковой панели); `--data-root` (умолчание `AICOACH_DATA_ROOT`) включает блок «Новый матч» (ссылка → фоновый `ingest`, необязательная загрузка `lineups.csv` в каталог матча), `--templates` передаётся каждому такому запуску; в таблице событий колонка «Игрок» (фамилии из `plate_names.json`); без `--video` интерфейс открывается без матча
python -m aicoach.cli eval       --match-id <ID> --split half2   # метрики, запуск в MLflow
python -m aicoach.cli clip       --video <PATH_TO_SRC_MP4> --event-id <EVENT_ID> [--before 8] [--after 12] [--match-id <ID>] [--db <FILE>]   # клип события (время из events_current, правки учтены) → clips/<id>_<тип>_t<мс>ms_b<до>_a<после>.mp4 рядом с видео; перекодирование H.264/AAC (D-056); готовый файл не режется заново; нужен ffmpeg в PATH
python -m aicoach.cli agent-eval --questions <FILE.csv> --video <PATH_TO_SRC_MP4> [--db <FILE>] [--match-id <ID>] [--provider openrouter|gemini] [--model <MODEL>] [--output <FILE>]   # агент (FR-8, D-061, D-068): вопросы (колонки id,type,question,expected,what_we_check) → answers.csv рядом с видео (колонка grade пустая, для ручной оценки) и сводка: сколько ответов прошло валидатор с первой попытки, со второй, отказы, ссылок всего, токены, время, стоимость; журнал agent_log.jsonl в каталоге матча; нужен ключ выбранного поставщика (см. «Настройки»); `--model` это имя модели поставщика (для `openrouter` с префиксом, например `openai/gpt-6-luna`; умолчание `AICOACH_AGENT_MODEL`, затем `openai/gpt-6-luna`, для `gemini` `GEMINI_MODEL`)
python -m aicoach.cli speech-test --video <PATH_TO_SRC_MP4> [--check-file <speech_check.txt>] [--lineups <lineups.csv>] [--no-vocabulary] [--provider openrouter|gemini] [--model <MODEL>] [--output <DIR>]   # тест расшифровки речи (D-066, D-068, не стадия пайплайна; через OpenRouter модели `google/gemini-3.5-transcribe` (умолчание) и `elevenlabs/scribe-v2`): фрагменты из `speech_check.txt` (строка `ЧЧ:ММ:СС - ЧЧ:ММ:СС kz|ru|mixed`, ниже услышанные слова) режутся из звука видео, расшифровываются (режим timed: слова с временем и говорящим, реплики с `t_v` и языком по буквам; при наличии `lineups.csv` ещё режим vocabulary: текст с фамилиями как подсказками); результат в `speech_test/` рядом с видео (вне git), в консоль сводка (найдено слов, ненайденные, языки реплик, время, токены, стоимость, куски речи длиннее 15 с без сегментов) и полный текст; `--no-vocabulary` пропускает второй запрос со словарём; нужны ключ выбранного поставщика и ffmpeg; живой тест: `$env:AICOACH_LIVE_LLM = "1"; $env:AICOACH_REAL_MATCH_VIDEO = "<src.mp4>"; pytest tests/integration/test_speech_live.py --no-cov`; живые тесты OpenRouter (доли цента): `$env:AICOACH_LIVE_LLM = "1"; $env:AICOACH_REAL_MATCH_VIDEO = "<src.mp4>"; pytest tests/integration/test_openrouter_live.py --no-cov`
python -m aicoach.cli final-eval --match-dir <MATCH_DIR> --tdeed <tdeed_*.json> [--ingest-dir <DIR>] [--model-db aicoach_model.db] [--nomodel-db aicoach_nomodel.db] [--gemini gemini_baseline_half2.txt] [--tdeed-threshold 0.2] [--ground-truth <FILE>] [--output docs/metrics.md] [--final]   # итоговые метрики (D-064): без --final только 1-й тайм (пороги на нём подбирались), 2-й тайм и сравнение Gemini-базы с эталоном только с --final; одна команда считает системы (a) без модели, (b) T-DEED без слияния, (c) слияние с моделью, (d) Gemini-база (Precision, Recall, F1 при ±5 и ±10 с, bootstrap 95 %, медиана и P90 ошибки), число правок (FP + FN), стоимость агента из agent_log.jsonl, состояния стадий из status.json; пишет docs/metrics.md
```

**Итоговая оценка (D-064).** `final-eval` читает только `predictions` последнего запуска каждой БД, не `edits`. Перед расчётом БД сверяются с пересчётом правил текущим `FuseConfig()`: расхождение (например, база снята до смены порога) останавливает оценку. База «без модели» для матча `match01` это `aicoach_nomodel.db` (`fuse` без `--predictions` с `--db`; `fuse` при этом перезаписывает `candidates.json` каталога видео, поэтому второй запуск делать в копии каталога). **2-й тайм считается один раз, после заморозки:** `python -m aicoach.cli final-eval --match-dir C:\Projects\data\match01 --tdeed tdeed_SoccerNet_small_thr0.05_bs2.json --ingest-dir C:\Projects\data\match01_ingest --final`; без `--final` вывод 2-го тайма отклоняется. Пример для разработки (только 1-й тайм): та же команда без `--final`.

**Агент (D17, FR-8, D-061).** Отвечает на вопросы о событиях матча по инструментам над `events_current`, `plate_names.json` и `lineups.csv`: `match_info`, `query_events` (вид, тайм, минуты игры, сторона, игрок, лимит), `get_event`, `find_player`, `make_clip` (если известно видео), `get_transcript` (слова комментаторов вокруг события, по умолчанию 20 с до и 20 с после, или за игровые минуты `half`/`minute_from`/`minute_to`) и `search_transcript` (слово, фамилия или прозвище; сопоставление `aicoach/namematch.py`). Куски комментария имеют id `s:N`, ссылка `[E:s:N]` рисуется как `🎙 23' · видео 38:12`; сказанное агент пересказывает как «комментатор сказал…», а не как факт; текст расшифровки это данные, не инструкции. Поставщик по умолчанию OpenRouter (D-068), модель по умолчанию `openai/gpt-6-luna` (D-071). **Как сменить модель:** на один запуск флаг `--model` (например `--model google/gemini-3.5-flash-lite`, `google/gemini-3.7-flash`, `anthropic/claude-haiku-5.5`); насовсем, включая панель «Агент», `AICOACH_AGENT_MODEL=<слаг OpenRouter>` в `.env` или в окружении (пусто: умолчание); модель без строки в `agent/pricing.py` работает, но без оценки стоимости до запроса; при `--provider gemini` модель берётся из `GEMINI_MODEL` (пусто: `gemini-3.5-flash-lite`, см. `config.py`); панель «Агент» берёт поставщика из `AICOACH_LLM_PROVIDER` (флагов у неё нет); цены для оценки стоимости лежат в `agent/pricing.py` с источником. В ответе модель пишет только ссылки `[E:<id>]`; метку (тип, тайм, минута, время видео) и ссылку YouTube `?t=` подставляет код; валидатор отклоняет id не из инструментов этого вопроса, текст, похожий на время или адрес, фамилии и числа цифрами не из инструментов этого вопроса или из текста вопроса (одна повторная попытка, затем отказ без ссылок; числа словами не проверяются; числа из аргументов `half`, `minute_from`, `minute_to`, `number` вызова тоже разрешены). Не больше 6 вызовов инструментов на вопрос; 429 и 5xx повторяются с паузами 4, 8, 16, 32 с. Системный промпт: `src/aicoach/agent/system_prompt.md` (без данных матча, команды подставляются при запуске). В интерфейсе панель «Агент» справа от плеера (D-062): прокручиваемая история фиксированной высоты (константа `AGENT_PANEL_HEIGHT_PX` в `ui/agent_panel.py`), поле вопроса внутри панели, сообщения пользователя справа, кнопка с меткой события переводит плеер на него; таблица событий под плеером на всю ширину. Агент видит карточки (фолы с плашкой карточки: `query_events` с `card=true`, поле `card`, фамилия с плашки), у замен обе фамилии (`substitution`), у выборки по `side` число событий без команды (`team_unknown`). Карточки: поле `card` это `yellow` или `red`; **красная карточка (плашка с красным заголовком) не проверена на реальных плашках**, в `match01` их нет, детектор проверен только на синтетике; вторая жёлтая показывается как жёлтая. Ссылки в ответах выглядят как `⚽ 23' · видео 38:12` (D-063). Для `match01` оценку агента запускать с `--db aicoach_model.db`. Транскрипт речи агент пока не читает. Единственный тест с настоящим Gemini: `$env:AICOACH_LIVE_LLM = "1"; pytest tests/integration/test_gemini_live.py --no-cov` (нужны ключ и сеть).

Весь пайплайн подряд (без модели, она идёт отдельно в Colab): `python -m aicoach.cli run --video <PATH_TO_SRC_MP4>`; стадии идут по порядку scoreboard, plates, fuse, каждая использует свой кэш, при сбое выполнение останавливается, а в `status.json` запись `run` называет стадию и причину. `--force` в `run` пересчитывает все стадии (видео читается дважды, это долго) и при наличии правок пользователя остановится только на третьей стадии, если не указан `--discard-edits`. Файл `--predictions` и `--config` проверяются до запуска первой стадии. Любая ошибка стадии выходит как `error: stage <имя> failed: ...` с кодом 2. У каждой стадии, запущенной через `run` или `ingest`, в `status.json` кроме состояния пишутся время начала и конца (ISO 8601, UTC) и длительность в секундах последнего запуска (`started_at`, `finished_at`, `duration_s`); у пропущенных (`skipped`) и ожидающих (`waiting`) стадий их нет; стадия, взявшая результат из кэша, оставляет время работы, которая его сделала, а если его не было, времени нет (D-065); у шага `tdeed` (поиск файла) времени нет; `final-eval` выводит их в разделе «Время стадий и стоимость». Статус стадий пишется в `status.json` каталога матча (для стадий `scoreboard`, `plates` и `fuse` это каталог видео).

**Стадия `scoreboard` (D03).** Видео передаётся только аргументом `--video`; результат (`scoreboard.json`, `status.json`) и образцы (`scoreboard_templates/`) лежат в каталоге видео, а не в репозитории. Без образцов стадия падает с подсказкой. Калибровка в два шага: шаг 1 строит эталон табло и пишет в `--workdir` листы `sheet_clock.png`, `sheet_score.png`, `sheet_added.png` (кластеры символов с номерами); человек смотрит листы и пишет файл подписей `{"clock": {"0": "colon", "1": "0"}, "score": {...}, "added": {...}}` (номер кластера → `0`..`9`, `colon`, `plus`); шаг 2 (`--labels`) режет образцы. Декодирование идёт на видеокарте, если она есть (`--cpu` отключает, для AV1 это в десятки раз медленнее); образцы и прогон должны идти в одном режиме, иначе стадия остановится. Результат кэшируется по ключу (видео, параметры, режим, образцы); `--force` читает видео заново.

**Стадия `plates` (D04, шаг 1).** Нужен `scoreboard.json` рядом с видео (без него понятная ошибка с подсказкой запустить табло) и тот же режим декодирования, что у табло (иначе остановка). Читает видео 2 раза в секунду (`--sample-fps`; `--cpu` декодирует на процессоре, `--match-id` по умолчанию имя каталога видео), находит плашки замены, гола и карточки по цвету и форме, склеивает кадры в плашки, определяет команду по логотипу и смене счёта. Фамилии не читаются (это следующий шаг). Пишет `plates.json`, `status.json` и `plate_crops/` (вырезка и логотип каждой плашки, вырезки отброшенных кандидатов) в каталог видео; всё вне git. Кэш по ключу (видео, версия `scoreboard.json`, режим декодирования, параметры и раскладка); `--force` читает видео заново. На матче `match01` стадия идёт около 9 минут на видеокарте.

**Стадия `fuse` (D09).** Читает `scoreboard.json`, `plates.json` и необязательный файл T-DEED (`--predictions`) из каталога видео; видео не читает. Правила и стартовые параметры: D-047 в `MEMORY.md`; параметры лежат в `FuseConfig`, нужное переопределяется JSON-файлом `--config` (неизвестное поле или неверное значение даёт ошибку конфигурации). Без `--predictions` стадия работает в режиме «без модели»: голы, замены и фолы по плашкам карточек, в `candidates.json` и в логе предупреждение. Пишет события в SQLite `aicoach.db` (таблица `predictions`, новый `run_id` на каждый запуск, D-028) и `candidates.json` (события с источником и доказательствами, отброшенные, предупреждения, границы таймов) и `status.json` в каталог видео. Кэш по ключу (версии трёх входных файлов, параметры, версия схемы) и по тому, что запуск из `candidates.json` всё ещё последний в базе; `--force` считает заново. **Защита правок (D-028):** если у матча есть действующие правки пользователя, а запуск записал бы новый `run_id`, стадия отказывается; после экспорта проверенных меток запускать с `--discard-edits` (журнал правок остаётся, но правки предсказаний пропадают из текущего вида). Пример: `python -m aicoach.cli fuse --video <PATH_TO_SRC_MP4> --predictions <PATH_TO_TDEED_JSON>`.

**Стадия `transcribe` (D-070).** Звук матча (`audio.wav`, иначе звук `src.mp4`) режется на куски по 180 с с перекрытием 10 с (лимиты OpenRouter: 25 МБ на запрос и около 60 с работы провайдера на запрос; MP3 32 кбит/с даёт 0,7 МБ на кусок). Каждый кусок идёт в модель (по умолчанию `elevenlabs/scribe-v2`: слова с временем и диаризацией), ответ сохраняется в `speech_chunks/chunk_NNNN.json`: прерванный запуск (сбой сервиса, бюджет `AICOACH_BUDGET_USD`) продолжается с первого куска без ответа, повторный запуск и новый состав не платят заново. Куски склеиваются без дублей (граница по середине перекрытия, слово принадлежит куску, чья часть содержит его середину), метки говорящих согласуются по перекрытию. Сегменты (`s:N`): время `t_start`/`t_end` в секундах видео, тайм (границы по `scoreboard.json`, как у `fuse`), говорящий, язык по буквам (эвристика D-066), текст и игроки, которых называет текст: фамилия (первое слово имени в `lineups.csv`) или прозвище из колонки `aliases` (прозвища через `;`, в файле с разделителем `;` ячейку взять в кавычки), с падежами и опечатками; два игрока с одной фамилией не угадываются. Дыры: отрезки внутри тайма от 15 с без речи, по таймам доля `gap_share`. Траты идут в журнал `spend_ledger.jsonl` (D-067). В `ingest` шаг стоит после `plate_names` и до ожидания T-DEED; без ключа OpenRouter он «пропущен» (`status.json`), сбой сервиса останавливает `ingest` (готовые куски сохранены). Транскрипт не пишется в `predictions` и `edits`.

**Стадия `plate_names` (D-059).** Читает `plates.json` и вырезки `plate_crops/` из каталога матча (видео не читает; 16 плашек за секунды). Для каждой плашки вырезается строка текста (одна у гола и карточки, две у замены: сверху вышел, снизу ушёл), картинка готовится (серый, ×3, порог Otsu, белая рамка), Tesseract `kaz+rus` в режиме одной строки читает её. Есть `lineups.csv` (колонки `team,side,number,name,position,started,minute_on,minute_off`, нужны `side` и `name`, UTF-8 с BOM или без, разделитель `,` или `;`): фамилия ищется среди игроков той же стороны, сходство ниже порога 0,88 даёт «не распознано», без угадывания. Нет состава: чищеный сырой текст со статусом `unchecked`. Результат `plate_names.json` (в `predictions` и `edits` не пишется); кэш по хешам `plates.json` и состава и параметрам, новый состав пересчитывает имена за секунды; `--force` читает заново. В интерфейсе имена видны в колонке «Игрок», состав можно загрузить в блоке «Новый матч». Пример: `python -m aicoach.cli plate-names --video <PATH_TO_SRC_MP4> --lineups lineups.csv`.

**Новый матч по ссылке, `ingest` (D15, FR-1, FR-2, D-058).** Каталог данных берётся из `--data-root`, иначе из `AICOACH_DATA_ROOT` (нет ни того ни другого: ошибка). Пример: `python -m aicoach.cli ingest "https://youtu.be/<ID>" --data-root C:\Projects\data --templates C:\Projects\data\match01\scoreboard_templates`. Ссылка разбирается до скачивания (`watch?v=`, `youtu.be/`, `/live/`, лишние параметры вроде `&t=` отбрасываются); каталог матча `<data-root>/<--match-id или id видео>/`. Шаги и записи `status.json`: `download` (yt-dlp, видео не выше 720p и звук, склейка в `src.mp4`, докачка `.part` при обрыве; затем проверка кадра 1280×720, иначе остановка: табло и плашки откалиброваны под этот размер), `audio` (`audio.wav` 16 кГц моно, FFmpeg), `scoreboard`, `plates`, `plate_names` (фамилии с плашек, шаг пропускается без Tesseract, идёт до ожидания T-DEED), `tdeed`, `fuse` (база `aicoach.db` в каталоге матча); общая запись `ingest`. Образцы табло (`scoreboard_templates/`) режет калибровка (D-030); для нового каталога они копируются один раз из `--templates` (каталог образцов откалиброванного матча той же трансляции), без них остановка до скачивания. Готовое пропускается: `src.mp4` и `audio.wav` не создаются заново, у табло, плашек и слияния свои кэши. Пока идёт обработка, второй запуск того же матча отклоняется (`ingest.lock` с pid процесса; замок умершего процесса снимается сам). Нужны `ffmpeg` в PATH и доступ к YouTube.

**Как продолжить после ноутбука T-DEED.** Если в каталоге матча нет файла `tdeed_*.json`, `ingest` останавливается после плашек с кодом выхода 3: запись `tdeed` в `status.json` получает `waiting`, в консоли инструкция. Обработайте `src.mp4` из каталога матча в ноутбуке T-DEED (перекодировать в 25 к/с без обрезки, `inference.py` с `--inference_threshold 0.05`, D-042, D-045), положите `results_inference.json` в каталог матча под именем `tdeed_<имя>.json` (например `tdeed_SoccerNet_small.json`; файл должен быть один) и запустите ту же команду `ingest` ещё раз: загрузка, звук, табло и плашки возьмутся из готового, дальше слияние. В интерфейсе то же делает блок «Новый матч» (`ui --data-root <DATA_DIR> --templates <DIR>`): кнопка «Обработать» запускает `ingest` отдельным процессом с журналом `ingest.log` в каталоге матча, список шагов обновляется раз в 2 с, после файла T-DEED нажать «Обработать» ещё раз, по готовности кнопка «Открыть матч».

**Экспорт клипа (D13, FR-7).** `clip` берёт время события из `events_current` (правки учтены), вырезает окно `[t_v − до, t_v + после]`, подрезанное по краям видео, и перекодирует его в H.264/AAC (копия потока не годится: исходник AV1 режется по ключевым кадрам). Клип лежит в `clips/` рядом с видео; имя содержит id, тип, время события в мс и поля, поэтому готовый файл отдаётся без ffmpeg, а сдвинутое событие получает новый клип. В интерфейсе то же делает кнопка «Экспорт клипа» в боковой панели. Подробности: D-056.

**Ветка B, T-DEED (D08).** Модель запускается в Colab неизменённым `inference.py` отдельным процессом; код T-DEED в репозиторий не копируется и не импортируется (D-046). Видео перед запуском перекодируется в 25 к/с без обрезки (шаг модели задан в кадрах, D-042); чтобы строки порогов 0,05 и 0,1 отличались от 0,2, `inference.py` запускается с `--inference_threshold 0.05` (D-045). Файл результата `results_inference.json` кладётся рядом с видео как `tdeed_<имя>.json` (вне git). Команда `spotting-eval` читает его и эталон, переводит `frame / fps` в секунды, оставляет шесть классов из 17 (D-043), сливает дубли ближе `--radius-s` (D-044) и для каждого порога считает Recall и Precision при ±5 и ±10 с, число найденных, медиану и p90 ошибки времени и bootstrap 95 % только по 1-му тайму; `--half 2` отклоняется, 2-й тайм зарезервирован для финальной оценки (D-045). Это не запуск MLflow, цифры в отчёт не идут. Эталон по умолчанию задан путём относительно текущего каталога, поэтому команду запускают из корня репозитория, иначе `--ground-truth`. Пример: `python -m aicoach.cli spotting-eval --predictions <PATH_TO_TDEED_JSON>`.

Тест по реальному матчу пропускается, пока не задана переменная окружения: `$env:AICOACH_REAL_MATCH_VIDEO = "<PATH_TO_SRC_MP4>"; pytest tests/real_data --no-cov` (нужны готовый `scoreboard.json` и, для плашек, `plates.json` и `plates_reference.json` с контрольными временами владельца рядом с видео).

## 7. Post-Task Workflow (обязательно)

Применяется к любой задаче, которая меняет файлы в репозитории. Чисто справочные ответы без изменений файлов этот процесс не запускают.

1. **Контроль качества.** Выполни `python scripts/check.py`. Если не зелёный, чини причину, а не проверку. Если починить не получается, не коммить: оставь изменения в рабочей директории и опиши блокер пользователю.
2. **Обнови `MEMORY.md`** (обязательно, если появилось что-то из списка):
   - новое решение: полный текст `D-xxx` (причина, статус) в `memory/decisions_full.md` и одна строка в оглавление `MEMORY.md`;
   - найденная проблема или закрытый вопрос: раздел «Известные проблемы»;
   - подход, который не сработал: запись `X-xxx` с числами и идентификатором запуска MLflow;
   - смена фокуса: раздел «Текущий фокус».
   Если ничего из этого не появилось, оставь файл как есть, но в отчёте напиши «MEMORY.md без изменений, потому что...».
3. **Обнови `SKILLS.md`**, если изменились команды, `scripts/check.py` или окружения. Файлы `CLAUDE.md`, `GIT.md`, `TESTING.md` без согласия пользователя не меняются: предложи правку в чате.
4. **Закоммить по правилам `GIT.md`:** отдельная ветка нужного формата; логически связанные изменения в одном коммите; формат Conventional Commits; код, тесты и обновления `MEMORY.md` и `SKILLS.md`, которые относятся к этому изменению, идут в одном коммите. Чисто «памятные» изменения идут как `docs(memory): ...`.
5. **Не делай `push` и `merge`** без явного «да» в чате.
6. **Отчёт пользователю на русском** (коротко): что сделано и зачем; хэши коммитов; результат `python scripts/check.py`; что записано в `MEMORY.md`; что дальше или что блокирует.

Если задача прервана и работа не доведена до рабочего состояния: не коммить, оставь изменения в рабочей директории и опиши их состояние в отчёте.
